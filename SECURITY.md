# Security / Безопасность публикации

## Что сделано в статическом сайте

- Контентная политика безопасности (CSP) через `meta http-equiv` — работает даже на GitHub Pages, но имеет ограничения.
- Встроенные атрибуты `style` удалены; JavaScript и CSS загружаются только из файлов собственного сайта.
- Нет внешних JavaScript-библиотек, веб-форм, аналитики или серверных ключей.
- Данные всех книг выводятся через `textContent`, а не через `innerHTML`.
- Внешние ссылки в новом окне имеют `rel="noopener noreferrer"`.
- Запрещён доступ скриптов к сторонним сетевым API (`connect-src 'none'`).
- Файл `_headers` готов для Netlify/Cloudflare Pages: HTTP CSP, защита от встраивания во фрейм, nosniff, Referrer-Policy, Permissions-Policy, HTTPS/HSTS.

## Важно для GitHub Pages

GitHub Pages **не применяет** файл `_headers`: дополнительные HTTP-заголовки, такие как `X-Frame-Options` и `frame-ancestors`, там нельзя активировать через файлы репозитория. Meta-CSP защищает лишь часть сценариев. Защита от вредоносных изменений зависит в первую очередь от безопасности учётной записи GitHub.

1. Включите двухфакторную аутентификацию GitHub, лучше аппаратный ключ/passkey.
2. Не добавляйте пароли, токены и приватные документы в репозиторий.
3. Проверяйте всё перед публикацией: **содержимое репозитория и PDFs будут публичными**.
4. Используйте Settings → Pages → Enforce HTTPS после подключения домена.
5. Если домен `kolesnik.engineer` зарегистрирован, подтвердите владение им в настройках GitHub до назначения Pages; избегайте wildcard DNS.
6. Права на изменения репозитория оставьте только у доверенных пользователей; при необходимости включите защиту основной ветки.
7. Если нужна серверная защита от встраивания сайта в iframe, разместите его на хостинге, где поддерживаются HTTP-заголовки из `_headers`.

Файл `CNAME` **не создаётся**, поскольку регистрация и фактическая настройка `kolesnik.engineer` не подтверждены.
